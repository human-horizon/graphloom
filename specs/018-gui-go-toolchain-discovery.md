# Обнаружение Go при запуске Graphloom из GUI

## Контекст

При запуске Graphloom из Finder приложение получает сокращённый `PATH`. Go analyzer запускается как бинарный sidecar, но `go/packages` внутри него вызывает команду `go`. Поэтому анализ Go-проектов завершается ошибкой `go command required, not found`, хотя Go установлен и доступен в терминале.

## Цель

Сделать запуск Go analyzer независимым от окружения Finder: Graphloom должен находить установленный `go`, передавать его каталог в `PATH` дочернему процессу и показывать понятную ошибку, если Go действительно не установлен.

## Что изменится

1. `src-tauri/src/analyzer.rs` — обнаружение executable Go в текущем `PATH` и через login shell, передача расширенного `PATH` Go sidecar.
2. `src-tauri/src/analyzer.rs` — unit-тесты сборки расширенного `PATH`.
3. `PROJECT_CONTEXT.md` — запись причины ошибки и решения.

## Детали реализации

1. Сначала искать `go` в `PATH`, унаследованном приложением.
2. Если он не найден, выполнить `command -v go` через login shell пользователя.
3. Если executable найден, добавить его родительский каталог в начало `PATH` только для процесса analyzer.
4. Если Go не найден ни одним способом, вернуть ошибку с указанием установить Go или добавить его в `PATH`; не запускать sidecar в заведомо нерабочем окружении.
5. Не менять глобальное окружение приложения и не хардкодить путь конкретной установки Go.

## Критерии приёмки

- [x] Go analyzer работает с `PATH=/usr/bin:/bin`, если Go доступен через login shell.
- [x] Текущий обычный `PATH` продолжает работать.
- [x] При отсутствии Go возвращается понятная диагностическая ошибка.
- [x] `cargo test` и `cargo clippy --all-targets -- -D warnings` проходят.
- [x] `CI=true pnpm typecheck` и `CI=true pnpm build` проходят.
- [x] `./scripts/install-mac.sh` переустанавливает приложение.
- [x] Graphloom успешно анализирует `/Users/a/Space/Projects/Starframe/abyss` из окружения установленного sidecar.
