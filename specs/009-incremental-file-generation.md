# Инкрементальная генерация диаграмм

## Контекст

Открытие проекта не должно запускать LLM. Генерация запускается только кнопкой `Update` и
последовательно обрабатывает файлы. Повторная генерация неизменённых файлов тратит время и
ресурсы, поэтому нужно запоминать хеш содержимого.

## Цель

Генерировать диаграммы только для новых и изменённых файлов, используя сохранённые результаты
для неизменённых файлов и показывая последовательный прогресс.

## Поведение

1. При открытии проекта статический анализ строит UCM и файловое дерево, но LLM не вызывается.
2. Для каждого исходного файла вычисляется SHA-256 содержимого.
3. В `.graphloom/state.json` сохраняется состояние файла:
   - относительный путь;
   - хеш содержимого;
   - ключ модели и версии промпта;
   - путь к последнему отчёту;
   - статус последней генерации.
4. Нажатие `Update` ставит в очередь только новые файлы и файлы с изменившимся хешем.
5. Неизменённые файлы получают статус `готово` из кэша без LLM-запроса.
6. Очередь обрабатывается строго последовательно, по одному файлу.
7. В дереве отображаются статусы `готово`, `ожидает`, `анализируется`, `ошибка`.
8. Во время очереди отображаются номер текущего файла, общее количество, имя файла и процент.
9. Старый отчёт изменённого файла сохраняется до успешного завершения новой генерации.
10. Удалённые файлы удаляются из состояния проекта.
11. Изменение модели, endpoint, версии промпта или renderer инвалидирует соответствующие
    кэшированные результаты.

## Изменения

- `src-tauri/src/state.rs` — типы состояния, SHA-256 и атомарное сохранение.
- `src-tauri/src/pipeline.rs` — расчёт плана обновления и последовательная генерация.
- `src-tauri/src/commands.rs` — команда получения плана и обновления одного файла.
- `src-tauri/src/lib.rs` — регистрация команд.
- `src/lib/ipc.ts` — типы и IPC-функции прогресса.
- `src/screens/Reports.tsx` — кнопка `Update`, статусы дерева и progress UI.
- `src/index.css` — компактные статусы и progress bar.
- `src-tauri/tests/e2e.rs` — проверка cache hit и обработки изменённого файла.

## Критерии приёмки

- [x] Открытие проекта не вызывает LLM.
- [x] Первый `Update` анализирует все файлы последовательно.
- [x] Повторный `Update` без изменений не вызывает LLM.
- [x] Изменение одного файла вызывает генерацию только для него.
- [x] В дереве и progress UI отображается актуальный прогресс.
- [x] Ошибка одного файла не прерывает очередь остальных файлов.
- [x] `cargo test`, `cargo clippy --all-targets -- -D warnings`, `pnpm typecheck`, `pnpm build` проходят.
