# Контекст проекта

[2026-08-24] Ошибка: `git diff --check` запущен в каталоге без Git-репозитория и завершился справкой Git → Решение: для проверки whitespace использовать `zsh -n`, `pnpm typecheck`, сборку и тесты; не использовать Git-команды в этом каталоге.
[2026-08-24] Ошибка: `open -a /Applications/Graphloom.app` сразу после переустановки вернул macOS error -600 → Решение: завершать старый процесс, ждать 1 секунду и запускать новый экземпляр через `open -n`.
[2026-08-24] Ошибка: после изменения renderer старые HTML продолжили отображаться из incremental cache → Решение: добавить `renderer_version` в cache key; изменения renderer теперь автоматически помечают старые отчёты pending. Позже заменено на полную перерисовку из DSL — renderer version больше не нужен.
[2026-08-24] Ошибка: при перерисовке готовых отчётов UI мог запускать `rerenderReport` параллельно и потенциально перетирать состояние → Решение: `refresh` делает последовательный rerender ready-файлов и ловит ошибки через `console.warn`.
[2026-08-25] Ошибка: LLM генерировал file/function-диаграммы с лишними узлами (33 узла на 80 строк), включая стандартные библиотечные вызовы, логирование и тривиальные проверки → Решение: обновлены промпты `file_map.md` и `function_flow.md` с ограничением 8-12/6-10 узлов и явным запретом на stdlib-утилиты и логирование; поднят `PROMPT_VERSION` в `state.rs` до `file-map-v2`, чтобы старые кэшированные отчёты инвалидировались. Graphloom.app переустановлен.
[2026-08-25] Ошибка: LLM указывал неверные номера строк в source-ссылках (например, подсвечивалась пустая строка вместо вызова) → Решение: в `validate.rs` добавлен `snap_node_source`: для узлов с `symbol` берётся точная позиция из UCM; для call/action/error/async узлов ищется ближайший UCM-call в том же файле (±5 строк) и подставляются его реальные start/end; итоговый диапазон clamp'ится к длине файла.
[2026-08-25] Semantic scope DSL v1 интегрирован end-to-end для Go file-level: Go analyzer выдаёт `entities` с AST-диапазонами и parent/children; Rust `semantic.rs` строит дерево, разворачивает в nodes+edges и применяет LLM-лейблы; `pipeline::analyze_file` теперь использует semantic tree + LLM labels; Qwen получает структурированное дерево и только лейблит. Mock server и fixture `labels.json` обновлены. `cargo test`, `clippy -D warnings`, `pnpm typecheck/build` — зелёные. Graphloom.app переустановлен. Осталось: TS analyzer entities, true tree renderer, cross_refs.
[2026-08-26] Ошибка: LLM часто возвращал labels JSON в markdown-огородке или с обрезанием, из-за чего apply_labels падал и использовал humanized-лейблы → Решение: apply_labels вырезает JSON из тела ответа; для project labels увеличен max_tokens до 8192. Теперь project/file/function labels применяются корректно на abyss.
[2026-08-26] Ошибка: cross_refs в renderer открывали только файл, но не функцию-цель → Решение: Reports.tsx при получении graphloom:navigate с symbolId/file сначала открывает файл, затем вызывает analyzeFunction для целевого символа и показывает его Flow.
[2026-08-26] Ошибка: install-mac.sh не пересобирал sidecar-ы после изменений исходников, оставляя устаревший Go/TS analyzer → Решение: sidecar build теперь безусловный (go build + pnpm build) в install-mac.sh.
